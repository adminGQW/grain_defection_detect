## 2. 开始一次训练

**先完成第 1 节，再把下面整行输入终端。CMD 和 PowerShell 都能使用这条单行命令。**

```bat
python benchmark_grain_4class_repvit_project_v3_eval_misclass_fixed.py --data_root "../Task_data_30_10_60_aug" --task_name grain4v3 --output_root ./results_grain4v3_20261023 --models repvit_v4 --seeds 2026 --epochs 30 --batch_size 64 --num_workers 8 --img_size 224 --lr 1e-4 --weight_decay 1e-4 --patience 8 --pretrained 1 --device cuda
```

保留你给出的训练设置，并把原本省略的默认参数显式写出，便于以后离线复现（用相同配置再次运行）。

**输出目录特意换成 `results_grain4v3_20261023`：**原来的 `results_grain4v3/grain4v3/repvit_v4/seed_2026/` 已有 `training_final_metrics.json`，照搬原输出目录会跳过训练。检查时新目录尚不存在。之后再次开展新实验时，也应使用新的目录名，例如 `results_grain4v3_20261023_run02`；已完成的新目录再次使用同样也会跳过。

### 参数说明：改什么就改哪一项

| 参数 | 本次值 | 通俗解释 |
| --- | --- | --- |
| `--data_root` | `../Task_data_30_10_60_aug` | 数据根目录；从 code 向上一级找到现成数据，里面有 train/val/test |
| `--task_name` | `grain4v3` | 实验名称，也是输出子目录；改名称不会自动改变分类任务 |
| `--output_root` | `./results_grain4v3_20261023` | 本次结果根目录，权重、训练日志和报告保存在这里 |
| `--models` | `repvit_v4` | 只训练 RepViT + DSK + DSG；DSK 组合不同观察范围的特征，DSG 让两路特征交互 |
| `--seeds` | `2026` | 训练随机种子（控制初始化、打乱等随机过程的起点编号）；只训练一次，与 MATLAB 数据划分 seed 独立 |
| `--epochs` | `30` | 最多训练 30 轮；一轮表示训练集完整经过一次 |
| `--batch_size` | `64` | 每批同时处理 64 张图；显存不足时可先降为 32 或 16 |
| `--num_workers` | `8` | 用 8 个子进程读取图片；不保证越多越快，Windows 读图报错时可先改 0 排查 |
| `--img_size` | `224` | 图片缩放成 224×224；展示界面也使用这个尺寸 |

| `--lr` | `1e-4` | 学习率（每次调整模型参数的步幅），等于 0.0001 |
| `--weight_decay` | `1e-4` | 权重衰减（限制参数过大的一种办法），等于 0.0001 |
| `--patience` | `8` | 验证指标连续 8 轮没有严格提高就早停，所以可能不到 30 轮 |
| `--pretrained` | `1` | 使用已有通用图像预训练参数作起点；没有缓存时可能下载 |
| `--device` | `cuda` | 使用 NVIDIA 显卡；不可用时当前脚本会回退 CPU |

本次参数与原参考命令的省略项默认设置一致；不是宣称这些超参数已验证为最佳方案。优先先跑同一套配置，再一次只改一个因素比较。

## 3. 训练结束后去哪里看

```text
code/results_grain4v3_20261023/grain4v3/repvit_v4/seed_2026/
├─ best_model.pth                 验证表现最好一轮的参数存档，不一定是最后一轮
├─ data_info.json                 类别顺序和数据数量
├─ train_log.csv                  每轮损失与训练/验证指标
├─ training_final_metrics.json    最终结果，也是再次运行时的跳过依据
└─ final_eval/
   ├─ val/                       验证报告、逐图预测、混淆矩阵、错分样本
   └─ test/                      测试集对应结果
```

验证集用于挑选训练轮次与调参；当前脚本训练结束后会自动用最佳权重分别评价 val 和 test。测试集用于最终评价，不应根据它的成绩反复挑参数。

`best_model.pth` 保存的不是完整的可恢复训练状态；脚本没有断点续训开关。中断后再执行原命令不代表从中断轮次接着训练。

## 4. 需要单独重算报告时：仅评估已有权重

训练已经完成且权重存在时才用这一条。它不会重新训练；输出单独存到评估目录。

```bat
python benchmark_grain_4class_repvit_project_v3_eval_misclass_fixed.py --eval_only --data_root "../Task_data_30_10_60_aug" --task_name grain4v3 --checkpoint_root ./results_grain4v3_20261023 --eval_output_root ./eval_results_grain4v3_20261023 --eval_split val,test --models repvit_v4 --seeds 2026 --batch_size 64 --num_workers 8 --img_size 224 --device cuda
```

`--eval_only` 是开关，后面不加 1；`--checkpoint_root` 必须对应训练时的 `--output_root`，任务名、模型名和 seed 也要匹配。训练已自动生成报告，通常无需立即再执行这一步；用于以后重新导出或检查。

重复评估会覆盖同名报告且可能残留旧错图，建议新一轮评估换一个新目录。若以后训练目录换名，也同步修改这条命令的 checkpoint_root。

### 6.2 第一条：通过完整路径激活 Conda 环境

```bat
conda activate E:\个人工作\pylib\py39torch2_dcnv4
```

意思是：使用该目录内的 Python 和已安装依赖。Conda 支持按**环境名称**或**环境完整路径**激活，不是只有一种写法：

| 写法 | 适用情况 |
| --- | --- |
| `conda activate E:\个人工作\pylib\py39torch2_dcnv4` | 环境实际安装在该路径，通过路径指定它 |
| `conda activate grain-defect-py311` | 当前电脑通过已登记的环境名称选择它 |

`py39torch2_dcnv4` 只是目录名，不能仅根据名字确认里面实际安装的 Python、PyTorch 版本或功能。激活不会复制环境、安装依赖，也不会启动训练；本机没有该旧路径时不能直接照搬。

### 6.4 第四条：训练一次 repvit_v4

这条命令的意思是：读取现成划分的数据，训练一个模型、一个随机种子，最多 30 轮，并保存结果。

| 命令片段 | 原样例的含义 |
| --- | --- |
| `python benchmark_...fixed.py` | 用已激活环境的 Python 执行训练脚本；这里缩写仅用于解释，执行时保留原完整文件名 |
| `--data_root "../Task_data_30_10_60_aug"` | 从当前 code 目录向上一层，找到已分好的 train/val/test |
| `--task_name grain4v3` | 给本次实验命名，并作为结果目录的一层 |
| `--output_root ./results_grain4v3` | 把结果放到当前 code 目录下的 results_grain4v3 |
| `--models repvit_v4` | 只运行 v4 网络，即 RepViT 骨干加 DSK 和 DSG 模块 |
| `--seeds 2026` | 使用训练种子 2026，只进行一次训练；不会重新划分 MATLAB 数据 |
| `--epochs 30` | 最多 30 轮，早停可能提前结束 |
| `--batch_size 64` | 每批读入 64 张图 |
| `--num_workers 8` | 使用 8 个子进程加载图片，不表示占用 8 张显卡 |
| `--img_size 224` | 预处理把图片缩放到 224×224 |

`../` 表示上一级，`./` 表示当前目录，均以终端当前目录为基准，不是自动以脚本位置为基准。`--models repvit_v4  --seeds` 中的两个空格不影响这里的参数解析。

原命令没有写出的项目，在**当前这份脚本**中使用以下默认值：

| 参数 | 默认值 | 解释 |
| --- | --- | --- |
| `--lr` | `1e-4` | 学习率 0.0001 |
| `--weight_decay` | `1e-4` | 权重衰减 0.0001 |
| `--patience` | `8` | 验证指标连续 8 轮未严格提高时停止 |
| `--pretrained` | `1` | 使用通用图像预训练参数；未缓存时可能下载 |
| `--device` | `cuda` | 优先使用 NVIDIA 显卡，不可用时按当前脚本逻辑回退 CPU |

不能仅凭这条历史命令断定原电脑当时用了哪些库版本；上表是当前源码默认配置，不是原电脑环境取证。

保存的最佳权重路径按下面规则拼接：

```text
output_root / task_name / model_name / seed_编号 / best_model.pth
```

所以原样例对应：

```text
code/results_grain4v3/grain4v3/repvit_v4/seed_2026/best_model.pth
```

当前脚本每轮依据验证集 Macro-F1 选择最好权重，训练完成后已经会对 val 和 test 分别导出结果。若输出目录已有 `training_final_metrics.json`，会跳过此次训练，不会自动比较参数或断点续训。

### 6.5 第五条：读取已有权重，仅评估

关键区别是多了 `--eval_only`。这条命令不会更新参数，而是加载上一条生成的 `best_model.pth`，重新计算指标和导出报告。

| 参数 | 含义与对应关系 |
| --- | --- |
| `--eval_only` | 开启仅评估模式，后面不加 1 |
| `--checkpoint_root ./results_grain4v3` | 从原训练结果根目录找权重，要与训练的 output_root 对应 |
| `--eval_output_root ./eval_results_grain4v3` | 将新报告存到另一根目录，不是修改权重路径 |
| `--eval_split val,test` | 分别评价验证集和测试集，不是把两个集合合并 |
| `--task_name grain4v3 --models repvit_v4 --seeds 2026` | 与训练时一致，用来拼出正确权重路径 |
| `--batch_size 64 --num_workers 8` | 控制评估时分批和读图，不代表重新训练 |
| `--img_size 224` | 保持与训练预处理约定一致 |

例如验证报告会存到：

```text
code/eval_results_grain4v3/grain4v3/repvit_v4/seed_2026/val/
```

这一步是可选的：训练已经导出报告时，不必马上重复评估。需要以后重算或单独检查已有模型时再用；找不到权重会提示跳过，不会自动补训。重复使用评估目录会覆盖同名报告，还可能保留旧错图。

## 13. 公司设备没有环境：从安装到启动识别

本节新增于 2026-10-23。**默认公司设备是 Windows 10/11、64 位 x86 电脑，目标先是运行现有单图识别展示。**如果实际是 Linux、ARM 工控板或其他设备，不能直接使用本文 Windows 安装包与环境压缩包。设备系统、显卡、驱动、联网情况目前尚未确认；以下是操作教程，不表示已在公司设备部署成功。

### 13.1 到公司之前，先问清楚这几项

| 要确认什么 | 对安装方案的影响 |
| --- | --- |
| 系统及处理器架构 | 确认 Windows x64；Linux/ARM 需另做匹配环境 |
| 只识别还是还要训练 | 只识别无需搬整套训练数据，不需要 MATLAB；训练则要带数据和训练配置 |
| 有无 NVIDIA 显卡、具体型号 | 没有可先走 CPU；有显卡还需确认所用 PyTorch 支持其型号 |
| 显卡驱动是否安装 | 在 CMD 输入 nvidia-smi；失败不一定表示无显卡，还可能是驱动问题 |
| 是否联网、能访问哪些下载站 | 决定联网安装，还是提前准备完整离线环境 |
| 软件安装权限和可用磁盘 | 确认公司允许的安装位置、驱动安装方式；GPU 环境需要预留数 GB 以上，实际看包大小 |
| 图片入口与速度要求 | 当前界面是人工选择单图；相机自动取图、产线通信、连续处理属于后续接口工作 |

CPU 是普通处理器，适合先跑通；GPU 是显卡计算，通常更适合加速。CUDA 是 NVIDIA 显卡的软件计算体系，AMD/Intel 显卡不能直接用本教程 CUDA 命令。

```text
└─ acceptance_images\       少量已知类别图片，用于现场核对
```

路径中的 D 盘只是例子，没有 D 盘就整体换成实际允许的目录。上面权重目录是 app.py 当前默认路径的示例；如果交付的是新训练模型，应带新权重并修改部署副本中的 CHECKPOINT_PATH，不能混用不同实验文件。

还应带一份文字说明：完整训练命令、类别顺序、输入尺寸、模型版本、骨干名称及权重来源。RepViT 默认骨干为 `repvit_m0_9.dist_300e_in1k`，若训练时设置过 `REPVIT_MODEL_NAME`，需明确记录并在部署时保持一致。

单图识别不需要 Task_data、MATLAB 或全部历史结果。但 app.py 会导入训练脚本，因此即使不训练，也仍需安装其顶层导入的 pandas、matplotlib、scikit-learn 等依赖，不能只装 torch。

### 13.3 联网设备：先安装 Conda 管理工具

如果公司已有可用 Conda，直接使用公司允许的环境管理方式，不重复安装。没有时可从 [Miniforge 官方页面](https://github.com/conda-forge/miniforge) 下载 Windows x86_64 安装器，按安装向导安装，例如放到 `D:\Miniforge3`；完成后从开始菜单打开 Miniforge Prompt。Miniforge 也提供 conda 命令，不要求购买或安装完整 Anaconda 软件套装。公司已有的软件分发方式优先。

在该终端中输入：

```bat
conda --version
conda create -n grain-deploy python=3.11 pip -y
conda activate grain-deploy
python -c "import sys; print(sys.executable); print(sys.version)"
```

`grain-deploy` 是新环境名称，与你电脑的 grain-defect-py311 可不同。必须确认解释器指向新环境，之后用 `python -m pip` 安装，减少把包装错环境的机会。Conda 创建环境这一步也需要下载 Python 等包，所以它不属于离线安装方案。

### 13.4 安装 PyTorch：CPU/GPU 二选一

截至本次读取，本机环境元信息如下；这是版本记录，不是公司设备兼容性验证：

```text
Python 3.11.17
torch 2.10.0+cu128
torchvision 0.25.0+cu128
timm 1.0.30
numpy 1.26.4
pandas 2.2.3
matplotlib 3.10.1
scikit-learn 1.7.0
pillow 12.2.0
tqdm 4.67.1
huggingface-hub 2.2.0
```

**方案 A：没有 NVIDIA 显卡，或先用 CPU 跑通。**在已激活 grain-deploy 的终端执行：

```bat
python -m pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cpu
```

**方案 B：使用 NVIDIA 显卡。**先执行：

```bat
nvidia-smi
```

确认型号和驱动，再按 [PyTorch 官方版本安装表](https://pytorch.org/get-started/previous-versions/) 选择匹配版本。下面是与本机相同的 CUDA 12.8 构建示例，**仅适用于显卡和驱动支持该组合的设备**：

```bat
python -m pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cu128
```

两条安装命令只选一条，不要在同一个环境反复混装 CPU/GPU 包。`torch` 与 `torchvision` 版本要配套，不能随意一个新一个旧。本工程没有音频功能，不需要为运行界面另装 torchaudio。

NVIDIA 驱动负责系统与显卡通信；CUDA Toolkit 是编译 CUDA 程序的开发工具集。对本工程使用的官方 PyTorch 预编译包，通常无需另外安装完整 Toolkit，但仍必须有兼容驱动。`nvidia-smi` 显示的 CUDA Version 不等于已经安装了完整 Toolkit，也不能单独证明 PyTorch 可用。若换到需要编译自定义 CUDA 算子的其他工程，要另行确认编译依赖。

### 13.5 安装其余依赖，并确认装对了环境

以下主依赖版本与当前电脑一致；它们的间接依赖仍由 pip 解析，所以不是完整环境锁定文件，也不保证未经检查就能在所有机器工作。

```bat
python -m pip install timm==1.0.30 numpy==1.26.4 pandas==2.2.3 matplotlib==3.10.1 scikit-learn==1.7.0 pillow==12.2.0 tqdm==4.67.1 huggingface-hub==2.2.0
python -m pip check
python -c "import torch, torchvision, timm, numpy, pandas, matplotlib, sklearn, PIL, tqdm; print('torch:', torch.__version__); print('torchvision:', torchvision.__version__); print('CUDA:', torch.cuda.is_available())"
```

`pip check` 检查已安装包声明的依赖是否冲突。CPU 方案显示 CUDA=False 是正常现象；GPU 方案若显示 False，则检查当前 Python、包是否为 CPU 构建、驱动与显卡支持情况，不要只反复安装 Toolkit。

若以后包来源或版本不可用，应在独立新环境验证替代组合并记录，不要无说明地改成全套最新版。安装失败时保留完整错误信息，区分网络访问失败、找不到对应 wheel 与 DLL 加载失败；wheel 是针对特定 Python/系统预编译好的安装包。

### 13.6 修改部署副本配置，启动页面

先检查 `D:\GrainDeploy\project\detect_ui\app.py`：

1. CHECKPOINT_PATH 指向实际带来的 best_model.pth。
2. `build_transforms(img_size=224)` 与训练输入相同。
3. 模型版本、类别顺序及 REPVIT_MODEL_NAME 与训练一致；不要通过篡改类别名称假装新模型支持其他缺陷。

在已激活 grain-deploy 的 Miniforge Prompt/CMD 输入：

```bat
cd /d "D:\GrainDeploy\project\detect_ui"
python app.py
```

随后打开浏览器访问 `http://127.0.0.1:8765`，选择已知图片并点击识别。终端需保持开启，按 Ctrl+C 停止。当前 app.py 使用已有存档并以 pretrained=False 建模，默认 RepViT 不需要重新下载预训练权重；若你换了外部模型或依赖远程配置的分支，要单独准备其缓存并验证断网可用。

确认能手动启动后，再改部署副本 `启动识别界面.bat` 中的 PYTHON 为该设备实际环境解释器路径，可用下面命令查询：

```bat
python -c "import sys; print(sys.executable)"
```

例如查询结果是 `D:\Miniforge3\envs\grain-deploy\python.exe`，则写：

```bat
set "PYTHON=D:\Miniforge3\envs\grain-deploy\python.exe"
```

不要继续使用你自己电脑的 `D:\ANACONDA\envs\grain-defect-py311\python.exe`。端口若修改，app.py 与 bat 的 URL 一起改；换权重时先停止旧服务，避免启动器复用旧模型。

### 13.7 公司完全断网：提前打包可用环境

**不能只带源码和 requirements.txt，也不能直接复制整个 Conda 环境文件夹后就假定可用。**requirements 只是包清单，包实体和 Python 本身还需要准备；直接移动环境可能留下原绝对路径。

可以使用 [conda-pack 官方迁移方案](https://conda.github.io/conda-pack/)：在联网的、与目标相同系统和架构的电脑上，先按上文创建并验证 grain-deploy，再打包。目标是 Windows x64，就在 Windows x64 上准备；GPU 方案还需匹配目标驱动与显卡，CPU 环境不能自动变成 GPU 环境。

下面是**联网准备电脑**的 CMD 操作示例，不是在断网公司设备上运行安装 conda-pack：

```bat
conda activate base
conda install -c conda-forge conda-pack -y
mkdir D:\GrainDeployBundle
conda pack -n grain-deploy -o D:\GrainDeployBundle\grain-deploy-win64.tar.gz
conda run -n grain-deploy python -m pip freeze > D:\GrainDeployBundle\requirements-record.txt
conda list -n grain-deploy --explicit > D:\GrainDeployBundle\conda-record.txt
```

这两份 record 文件用于记录版本，不是仅凭它们就能断网重装；以压缩包提供实际环境。打包工具需要原 Conda 包缓存，缓存被清理或环境文件异常时可能失败；应在联网准备阶段解决，不能带一个未完成的包到现场。不要用忽略丢失文件的选项掩盖不完整环境。

把环境压缩包、工程运行文件、权重、配置记录、已知类别图片一起带到公司。若采用 GPU 方案且目标尚无驱动，还需准备适合该设备的官方驱动安装包并按公司允许的方式安装；环境压缩包不会安装系统驱动。

在**公司 Windows CMD** 中，把压缩包放在示例路径后执行：

```bat
mkdir D:\GrainDeploy\env
tar -xzf D:\GrainDeployBundle\grain-deploy-win64.tar.gz -C D:\GrainDeploy\env
call D:\GrainDeploy\env\Scripts\activate.bat
conda-unpack
python -c "import sys, torch, timm; print(sys.executable); print(torch.__version__); print(torch.cuda.is_available())"
cd /d "D:\GrainDeploy\project\detect_ui"
python app.py
```

要求解压到空的最终环境目录；`conda-unpack` 修正包内原路径。Windows 的 tar 若不可用，可使用能正确解开 tar.gz 两层的解压工具。此方案不要求目标预装 Conda/Python，但是否缺少系统运行库仍需现场核对。完成 conda-unpack 后不要再移动这个环境；要换位置就从原压缩包重新解压到新的最终目录，再修正路径。

离线方案的 bat 中 PYTHON 应改为 `D:\GrainDeploy\env\python.exe`。如果直接用该解释器启动遇到 DLL 搜索问题，先在已执行 Scripts\activate.bat 的终端中运行排查，不能只认解释器路径存在就认定所有动态库已可用。

离开联网准备电脑前，先在独立目录解压验证，并断网尝试识别；拷包/安装依赖本身不等于部署验收。不要只用现有一直运行的旧服务验证，否则可能没有实际加载新交付文件。

### 13.8 另一种离线方式：wheel 安装包目录

如果公司已经有正确 Python/Conda 环境，只缺 Python 包，可以准备 wheelhouse（离线安装包文件夹）。在匹配 Windows x64、Python 3.11 的联网环境中，以 CPU 版本为例：

```bat
mkdir D:\GrainDeployBundle\wheelhouse
python -m pip download --only-binary=:all: --dest D:\GrainDeployBundle\wheelhouse torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip download --only-binary=:all: --find-links=D:\GrainDeployBundle\wheelhouse --dest D:\GrainDeployBundle\wheelhouse torch==2.10.0+cpu torchvision==0.25.0+cpu timm==1.0.30 numpy==1.26.4 pandas==2.2.3 matplotlib==3.10.1 scikit-learn==1.7.0 pillow==12.2.0 tqdm==4.67.1 huggingface-hub==2.2.0
```

第二条通过本地 find-links 复用第一条下载的 CPU 包，并显式指定 +cpu，避免解析依赖时换成其他构建。若第一条未成功下载，不要跳过错误继续执行。准备后必须在空白的匹配环境中按下方离线命令验证依赖完整性，失败则回到联网设备补包。

在公司已有的匹配环境激活后，安装 CPU 包：

```bat
python -m pip install --no-index --find-links=D:\GrainDeployBundle\wheelhouse torch==2.10.0+cpu torchvision==0.25.0+cpu timm==1.0.30 numpy==1.26.4 pandas==2.2.3 matplotlib==3.10.1 scikit-learn==1.7.0 pillow==12.2.0 tqdm==4.67.1 huggingface-hub==2.2.0
python -m pip check
```

`--no-index` 表示不访问线上包索引，`--find-links` 指向本地安装包。此方法**不提供 Python、Conda、显卡驱动或 Windows 运行库**；设备完全空白时优先使用上面的完整环境打包方案。GPU wheelhouse 应另做一个目录，下载并固定兼容 CUDA 构建，不要混入 CPU 包。

### 13.9 现场验收与故障定位

| 检查项／现象 | 该怎么判断或处理 |
| --- | --- |
| 能 import 全部依赖，pip check 无冲突 | 证明基本 Python 依赖可用，不证明模型正确 |
| 页面打开、API 成功返回 | 证明当前本机展示链路可用，不证明产线指标达标 |
| 已知图片在两台设备上类别/分数明显不同 | 对照权重文件、骨干、类别顺序、224 预处理和库版本；浮点微差不必然代表错误 |
| torch/torchvision 算子找不到 | 检查两者版本和 CPU/CUDA 构建是否配套，确认安装到了当前环境 |
| DLL load failed | 记录具体 DLL/包名；检查架构、运行库、激活环境及驱动，不靠重复复制文件解决 |
| 缺少 Microsoft VC++ 运行库 | 按错误与官方说明确认后安装 Microsoft Visual C++ x64 Redistributable；不要下载来源不明的单个 DLL |
| 权重找不到／结构不匹配 | 检查 app.py 的 CHECKPOINT_PATH 与 build_model 对应版本和骨干 |
| 断网时仍请求下载 | 查是否启用了 pretrained 或换了远程模型分支，准备实际依赖缓存；默认 UI 应使用已有权重 |
| 浏览器无法访问 | 查看服务终端是否正常启动；本机使用 127.0.0.1:8765，端口一致 |
| 别的电脑访问不了 | 当前服务仅监听本机地址，本文是单机部署；多机访问、权限和网络配置需另设计 |
| 推理太慢 | 记录图片尺寸、设备、单张耗时与实际需求，再决定 GPU/批量或其他优化，不先宣称实时达标 |

建议最少保留：交付权重、完整代码、依赖版本、设备型号/驱动、类别定义，以及一组固定图片的核对结果。推理指用训练好的模型判断新图；这里没有把公司设备重新训练作为启动识别的前提。
