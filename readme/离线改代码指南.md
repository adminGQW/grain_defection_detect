## 1. 先建立全局认识

| 需求 | 首选位置 | 同时检查什么 |

### 一个很容易改错的例子：Dropout

Dropout 是训练时随机暂时关闭一部分特征的办法，目的是降低对少数特征的过度依赖。假设你想把当前 v4 分类头从 0.20 调成 0.30：

1. 找到 `build_model` 中包含 `"repvit_v4"` 的分支。
2. 只改这个分支传入的 `dropout=0.20` 为 `dropout=0.30`。
3. 换一个新实验输出目录，并把这个改动写入实验记录。
4. 训练后比较验证指标，再按事先确定的规则使用独立测试集。

`RepViTProjectNet` 的默认值与这个分支显式传入的值不是同一层配置。DSG 内部的 `dropout=0.0` 又是另一个位置，不能认为它们一起改变了。

## 6. 模型代码怎样对应图片数据

张量是多维数字数组，`[B,C,H,W]` 分别表示一批图片数量、特征通道数量、高、宽。常见输入为 `[B,3,224,224]`，网络内部通道数通常不再是 3。

DSK 的流程：同一特征分别经过三种范围的卷积，选择器为每个空间位置给出三路权重，再加权相加。这里三路权重不是三种缺陷的分类概率。

DSG 的流程：同一特征经过两条独立分支，在对应位置相乘，投影回原通道数，再加回输入。这种“加回输入”叫残差连接，可以保留原有信息。

分类头最后输出 `[B,类别数]` 的 logits，即各类原始分数。`CrossEntropyLoss` 直接接 logits。展示时才用 Softmax 将分数变成非负且总和约为 1 的数值，再取最大类。

修改模块时先纸上核对三件事：

1. 并行分支相加/相乘时，形状是否匹配。
2. 残差 `x + ...` 的两边是否保持同样通道和宽高。
3. 最后 Linear 输入通道、输出类别数是否匹配。

若增加第 4 个 DSK 分支，必须同步卷积定义、`forward` 分支计算、选择器输出通道 `3` 和加权求和代码。只增加一个卷积定义不会让它自动参与预测。

## 7. 如何确认自己的改动真正生效

1. 先复制代码，记录原命令、数据版本、来源与划分方式、骨干名称、seed 和修改理由。
2. 搜索目标名称，确认主流程确实调用到它，且没有显式传参覆盖你改的默认值。
3. 使用新输出目录。若日志出现 `[Skip] Existing final training result found`，说明读了旧结果，并未按新参数训练。
4. 只查 Python 语法时可执行下面命令，它不训练，但会写入 `__pycache__` 缓存；语法通过不代表模型形状正确或准确率达标。

```bat
python -m py_compile benchmark_grain_4class_repvit_project_v3_eval_misclass_fixed.py
```

5. 真正运行后检查类别名、Train/Val/Test 数量、输出路径、是否出现跳过、是否发生 CPU 回退。
6. 看 `train_log.csv` 中的实际训练轮次、验证分数和学习率；修改 epoch 上限但实际早停时，要记录实际结束轮次。
7. 网络结构改动需做小范围前向/训练检查，确认维度和梯度，再开展正式比较；本轮未代你运行这些检查。

| 文件 | 看什么 |
| --- | --- |
| `data_info.json` | 类别顺序、每集合图片数 |
| `train_log.csv` | 每轮损失、训练/验证指标与学习率 |

| `training_final_metrics.json` | 本次完成标志与最终汇总；存在时下次训练会跳过 |
| `final_eval/val/` | 最佳权重的验证集报告、矩阵、逐图记录 |
| `final_eval/test/` | 同一权重的测试集结果 |
| `*_predictions.csv` | 每张图片的路径、真实/预测类、各类得分 |
| `*_misclassified_samples.csv` | 错分图片及错误类型；查看复制状态是否成功 |
| `*_binary_project_metrics.csv` | 合并为正常/缺陷后的误报、漏检等指标 |

Accuracy 是总体判对比例；Macro-F1 是各类 F1 等权平均；F1 综合考虑“判成这类的有多少是真的”和“真实这类找回多少”。类别不均衡时不能只看总体准确率。

缺陷 A 判成缺陷 B：四分类错；“有无缺陷”二分类对。因此 `4-class errors` 可以大于 `FP+FN`，不是两套结果互相矛盾。

当前汇总表按每个 seed 单列，并按测试分数排序，不能称作跨 seed 均值比较。部分旧版辅助函数的文字仍写均值，源码注释已标明区别；不要直接拼接不兼容的旧表格函数。

## 10. 数据准备的三个边界

**路径边界：**工程内部确实也有 `Task_data`；`main.m` 的相对路径是否正确取决于 MATLAB 的当前工作目录。不要仅依据 ZIP 外层另有同名目录就修改路径。

**覆盖边界：**三种划分函数都会删除已有输出目录后重建；重命名函数会真实移动文件名。它们不是无副作用的查看工具，已有划分训练时无需重跑。

**来源边界：**`groupAware=true` 只按文件名推断来源组。原图切块、翻转变体、同一晶粒不同拍摄视角是否被正确归组，需要真实来源记录核实；无来源信息时，把开关改成 true 也不能保证没有泄漏。

## 11. 自测与答案

**题 1：我把学习率改了，但程序显示 Skip，算新实验吗？**  
答案：不算。该目录已有完成结果，程序直接读旧结果。用新的结果目录，并确认启动日志和新日志文件。

**题 2：修改类定义中的默认 dropout，为什么可能没有变化？**  
答案：调用处显式传入了值，例如 v4 分支的 `dropout=0.20`，它会覆盖默认值。应检查实际调用链。

**题 3：界面把某个中文标签改成“划痕”，模型就会识别划痕了吗？**  
答案：不会。中文名只是展示。新类别需要对应标注数据、训练和一致的类别映射。

**题 4：四分类错了 14 张，但 FP+FN=12，可能吗？**  
答案：可能。另 2 张可能是缺陷之间互相混淆，有无缺陷仍判断正确；需要逐图记录才能确定具体原因。

**题 5：groupAware=true 就能放心报告真实泛化能力吗？**  
答案：不能。必须确认文件名分组与真实来源相符，并有独立、可信的评价数据；开关本身不能证明这一点。
